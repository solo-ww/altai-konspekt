# Подготовка к датасетам с царапинами

Задача: пришлют записи с **царапинами разной силы** → нужно правильно определить дефект и отправить результат.

## Главная проблема

Классификатор на «Алтае» сейчас считает признаки **только по прямому спектру 0–150 Гц**
(`analysis/synth/common.py`, `FMAX = 150`). А царапина физически даёт **удары**, которые прямой спектр
почти не видит (0–18 %, см. [01_методы_анализа.md](01_методы_анализа.md)).
Удары ловит только **ВЧ-огибающая с выбором полосы** — её на чипе пока нет.

→ Если ничего не менять, царапины, скорее всего, будут пропущены.

## Что нужно сделать

1. **Добавить признаки ВЧ-огибающей** (BPFO, BPFI, 2·BSF в спектре ВЧ-огибающей) в термометрическое
   кодирование → больше входов у сети → переобучить `train_ternary.py`.
2. **Добавить в синтетику ударные дефекты** при обучении сети (сейчас она учится только на модуляции;
   генератор ударов уже есть — `inject_impacts` в `common.py`).
3. **Слабые дефекты:** сейчас ловятся 2/12. Попробовать понизить порог (`compare_methods.py --sens 3`)
   и посмотреть, сколько вырастет ложных тревог.
4. **Проверить на настоящих дефектах.** Записи, вероятно, из открытого датасета KAIST (Mendeley Data,
   `ztmf3m7h5x`), где есть метки → найти метки и прогнать алгоритм на реальных неисправностях.
5. **Норма для сравнения** считается по этим 45 записям. Если новые данные с другого режима/стенда —
   пересчитать.

# «Алтай»: что это, как работает, как с ним взаимодействовать

## 1. Зачем вообще нейроморфный чип

Обычная нейросеть гоняет дробные числа через все нейроны на каждом шаге — много умножений, много энергии.
**Спайковая нейросеть (SNN)** работает как мозг: нейрон молчит, пока не накопит сигнал, и только тогда
выдаёт импульс. Передаются только события «был импульс / не было» → где тишина, там нет вычислений →
энергии в разы меньше. Цель: датчик, который сидит прямо на двигателе и годами работает от батарейки.

## 2. Что такое спайк

**Спайк** — короткий импульс, событие «1 в момент времени t». Вся информация — в том, *какой* нейрон
выстрелил и *когда*. Нет «0,734» — есть только «бип» или тишина.

Чтобы подать на чип обычные числа, их **кодируют в спайки**. В проекте — термометрический код:
число сравнивается с порогами 6, 9, 12, 16, 20, 24 дБ, и «загорается» столько битов, сколько порогов
пройдено (как полоски громкости на телефоне).

```
превышение 13 дБ  →  [1 1 1 0 0 0]   (больше 6, 9, 12; меньше 16)
превышение  4 дБ  →  [0 0 0 0 0 0]
```

## 3. Нейрон LIF — «протекающее ведро»

Leaky Integrate-and-Fire:

1. **Integrate** — входящие спайки доливают в ведро воду, каждый своё количество (**вес** синапса).
   Отрицательный вес — вычерпывает (**тормозящая** связь).
2. **Leaky** — вода понемногу вытекает (**утечка**).
3. **Fire** — уровень (**мембранный потенциал**) дошёл до **порога** → нейрон выдаёт спайк.
4. **Reset** — ведро опустошается.

В проекте настроено максимально просто: утечка 0, потенциал обнуляется каждый шаг. Значит нейрон просто
проверяет: **сумма весов активных входов ≥ порог?** Веса только **−1, 0, +1**, порог — целое число.

**Пример из `analysis/synth/weights.csv`:** нейрон «наружное кольцо» — порог 1, единственный вес +1 на входе
«BPFO выше нормы на 6 дБ». Поднялась боковая полоса BPFO на 6+ дБ → нейрон стреляет.
Нейрон «внутреннее кольцо» — +1 за BPFI и −1 за признаки чужих дефектов, чтобы не путать типы.

## 4. «Алтай», KNP и golden model

- **AltAI («Алтай»)** — российский нейроморфный процессор. В железе выполняет только спайковые сети с
  ограничениями: целые веса и пороги, свой тип нейрона **AltAILIF**.
- **KNP (Kaspersky Neuromorphic Platform)** — открытый фреймворк на C++: в нём собирают спайковую сеть
  и запускают на разных «бэкендах» (CPU или «Алтай»).
- **Golden model** — эталонная программная копия чипа, повторяет его побитно. **Физического чипа нет —
  работаем на эмуляторе.** В проекте все спайки эмулятора совпали с Python-эталоном бит в бит (2964/2964).

## 5. Словарь KNP

| Понятие | Что это | Аналогия |
|---|---|---|
| Neuron (AltAILIF) | нейрон: порог, утечка, сброс | ведро |
| Population | группа одинаковых нейронов (у нас 9) | ряд вёдер |
| Synapse | связь «вход i → нейрон j» с весом и задержкой | трубка с краном |
| DeltaSynapse | простейший синапс: при спайке добавляет вес к потенциалу | — |
| Projection | набор синапсов от источника к популяции (у нас 60 ненулевых) | вся сантехника |
| Network | популяции + проекции | схема |
| Model | сеть + входной и выходной каналы | схема с кранами |
| Backend | на чём считать: CPU или «Алтай» (`.so`-библиотека) | двигатель |
| ModelExecutor | гоняет модель по шагам, подаёт и собирает спайки | водопроводчик |
| Step | такт времени; у нас 1 шаг = 1 кусок записи 10 с | тик |

## 6. Сеть в нашем проекте

```
42 входа (7 признаков × 6 порогов)  ──►  9 нейронов AltAILIF
                                          0–5: тип дефекта (наружн., внутр., шарик, сепаратор, дисбаланс, расцентровка)
                                          6–8: степень (слабая / средняя / сильная)
```

Расшифровка на компьютере: выстрелил ровно один нейрон типа → этот дефект; ни одного → норма;
несколько → «??». По 6 кускам записи (6 × 10 с) — голосование.

## 7. Как Python общается с «Алтаем»

```
Python (analysis/synth/chip.py)            Docker-контейнер (Linux x86-64)
───────────────────────────────            ───────────────────────────────
weights.csv ─┐                             altai-fault-classifier (C++, KNP)
in.csv       ├──► knp-lab/chip_io ───────►   1. грузит бэкенд «Алтая»
             │    (общая папка)              2. собирает сеть из weights.csv
out.csv    ◄─┘ ◄─────────────────────────    3. подаёт спайки по шагам, пишет ответ
                  запуск через docker exec
```

- **weights.csv** — первая строка `42,9`, дальше по строке на нейрон: `порог,w0,w1,…,w41`.
- **in.csv** — строка = шаг, в ней номера выстреливших входов, например `12,18,19` (пустая — тишина).
- **out.csv** — строки `шаг,нейрон`: кто и когда выстрелил.

Два контейнера:
- `knp-lab` — «Алтай» (golden model) на KNP **v1.0.0** — основной;
- `knp-run` — тот же нейрон на CPU-бэкенде KNP **v2.0.0** — для сверки.

## 8. Как запустить (шпаргалка)

Один раз собрать контейнеры (из корня репозитория):

```bash
bash knp-lab/setup_docker.sh
```

После перезагрузки:

```bash
docker start knp-run knp-lab
```

Дальше из `analysis/synth/`:

```bash
python chip_eval.py altai-v1
```

```bash
python infer_blind.py altai-v1
```

```bash
python diagnose_file.py syn_07.csv altai-v1
```

## 9. Грабли

- Бэкенд «Алтая» из **v2.0.0 падает** на любой сети. Работает v1.0.0 с патчем: в ядро перенесён метод
  `Backend::select_device` из v2 (`knp-lab/patches/knp-v1.0.0.patch`).
- В v2.0.0 не хватает `SynapticResourceSTDPAltAILIFNeuron` — добавлен патчем `knp-v2.0.0.patch`.
- Пакеты бэкенда только под x86-64 → на Mac с M-чипом всё идёт через эмуляцию, медленно.
- В MATLAB путь к docker прописан как `/usr/local/bin/docker` — поправить, если стоит в другом месте.
- «Алтай» создаёт входы только для тех номеров, у которых есть синапсы → в `in.csv` неподключённые
  входы отфильтровываются (это делает `chip.py`).
